# Выкат обновления на сервер (из сети ОшГУ)

Обновление лежит в ветке `improvements-2026-10` на ноутбуке. Всё проверено на локальной копии сайта в WSL: 150 автотестов проходят, запуск кода и проверка решений работают на всех языках.

Перед выкатом: не делать во время олимпиады, занимает около 30 минут, сайт перезапускается на несколько секунд.

## 0. Сначала безопасность

1. Сменить пароль `samat1` на сайте (он был в DEVOPS.md в публичном репозитории; из файла я его убрал, но в истории GitHub он остался).
2. Сменить пароли SSH `admin` на обеих машинах: они были отправлены в общий чат проекта.

## 1. Один раз: git-репозиторий на сервере (CI/CD)

На olymp.oshsu.kg код сейчас не под git. Делаем «голый» репозиторий, в который ноутбук будет пушить, а хук будет выкатывать.

На сервере:

```bash
git init --bare /home/admin/olymp.git
cp /var/www/olymp.oshsu.kg/scripts/server/post-receive /home/admin/olymp.git/hooks/ 2>/dev/null || true
```

Скрипта ещё нет на сервере, поэтому хук скопируем после первого выката (шаг 3).

На ноутбуке (в D:\projects\olymp.oshsu.kg):

```bash
git remote add server admin@10.10.8.226:/home/admin/olymp.git
git push server improvements-2026-10:main
```

## 2. Настройки сайта (olymp.oshsu.kg)

В `/var/www/olymp.oshsu.kg/dmoj/local_settings.py` добавить в конец:

```python
DMOJ_RUNNER_PUBLIC_URL = '/runner'
DMOJ_RUNNER_SECRET_FILE = '/home/admin/runner.secret'
```

Создать общий секрет (тот же файл потом копируется на judge):

```bash
head -c 32 /dev/urandom | base64 | tr -d '/+=' > /home/admin/runner.secret
chmod 600 /home/admin/runner.secret
```

В конфиг nginx (`/etc/nginx/sites-available/olymp.oshsu.kg`) добавить внутрь `server { ... }` и поменять лимит загрузки:

```nginx
client_max_body_size 64M;

location /runner/ {
    proxy_pass http://10.10.8.227:9910/;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_read_timeout 120s;
    proxy_send_timeout 120s;
    client_max_body_size 2M;
}
```

Потом `sudo nginx -t && sudo systemctl reload nginx`.

## 3. Первый выкат

```bash
cd /var/www/olymp.oshsu.kg
git --git-dir=/home/admin/olymp.git --work-tree=/var/www/olymp.oshsu.kg checkout -f main -- scripts/deploy.sh scripts/rollback.sh
bash scripts/deploy.sh main
cp scripts/server/post-receive /home/admin/olymp.git/hooks/post-receive
chmod +x /home/admin/olymp.git/hooks/post-receive
```

`deploy.sh` сам делает бэкап базы и кода в `/var/backups/olymp/deploy/<дата>`, ставит пакеты (в том числе `openpyxl` для Excel), скачивает редактор Monaco, применяет миграции 0159–0162, собирает переводы и статику, перезапускает сайт и проверяет, что он отвечает.

Если что-то пошло не так: `bash scripts/rollback.sh /var/backups/olymp/deploy/<дата>` (только код) или с `--database` (код и база).

Скрипт вызывает `sudo` (бэкап базы и перезапуск служб). Чтобы выкат через `git push` не останавливался на вопросе пароля, добавить правило `sudo visudo -f /etc/sudoers.d/olymp-deploy`:

```
admin ALL=(root) NOPASSWD: /usr/bin/systemctl restart olymp-web olymp-bridge
admin ALL=(postgres) NOPASSWD: /usr/bin/pg_dump, /usr/bin/pg_restore
```

Дальше каждый выкат — это `git push server improvements-2026-10:main` с ноутбука. Перед пушем запустить проверки:

```bash
wsl -d Ubuntu-24.04 -u root -- bash /mnt/d/projects/olymp.oshsu.kg/scripts/ci_check.sh
```

## 4. Машина проверки (judge.oshsu.kg)

Новые языки и служба запуска кода ставятся сюда.

```bash
# скопировать с сайта (с olymp.oshsu.kg) нужные файлы
scp admin@10.10.8.226:/var/www/olymp.oshsu.kg/scripts/judge/install_languages.sh /tmp/
mkdir -p /home/admin/olymp-runner
scp admin@10.10.8.226:/var/www/olymp.oshsu.kg/runner/server.py /home/admin/olymp-runner/
scp admin@10.10.8.226:/home/admin/runner.secret /home/admin/olymp-runner/runner.secret
chmod 600 /home/admin/olymp-runner/runner.secret

sudo bash /tmp/install_languages.sh
```

Скрипт напечатает строки для раздела `runtime:`. Добавить их в `~/judge-config/judge.yml` и `~/judge-config/judge2.yml`. Node.js нужен именно 22 из `/opt/node22`: с Node 18 из Ubuntu не работает чтение ввода `readFileSync(0)`.

Служба запуска кода:

```bash
sudo cp /tmp/olymp-runner.service /etc/systemd/system/   # файл scripts/systemd/olymp-runner.service
sudo systemctl daemon-reload
sudo systemctl enable --now olymp-runner
sudo systemctl restart olymp-judge olymp-judge2
```

Порт 9910 открыть только для сайта, как и 9999:

```bash
sudo iptables -A INPUT -p tcp --dport 9910 -s 10.10.8.226 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 9910 -j DROP
```

(и добавить эти правила туда же, где сохранены правила для 9999).

Проверка самопроверкой судьи: `~/judge-server/venv/bin/dmoj -c ~/judge-config/judge.yml --self-test` должен показать `GO`, `KOTLIN`, `NODEJS`, `PAS` со словом Success.

## 5. Проверить после выката

1. Открыть любую задачу, нажать «Решать в редакторе», нажать «Запустить» и «Проверить на примерах».
2. Отправить решение на Python и на Go, дождаться «Принято».
3. Открыть «Песочницу», создать папку и файл, запустить.
4. В админке открыть «Импорт задачи из файла» и загрузить шаблон условия.
5. На странице олимпиады (под админом) видны кнопки «Продлить», «Итоги в Excel», «Нарушения».
6. В `/status/` оба судьи онлайн, в списке языков есть JavaScript, Go, Kotlin, Pascal.

## 6. Нагрузка и балансировщик

Сейчас: сайт — gunicorn с 4 процессами на одной машине, проверка — два судьи на judge.oshsu.kg, мост сам раздаёт решения свободному судье. Для олимпиады на 40–100 человек этого хватает с запасом. Запуск кода в редакторе идёт напрямую на judge через nginx и не занимает процессы сайта; служба запуска работает с пониженным приоритетом и ограничена двумя программами одновременно и 20 запусками в минуту на человека, так что проверку решений она не тормозит.

Если участников станет больше:

1. Больше судей. Самый простой шаг: ещё один `olymp-judge3` на той же машине (если есть свободные ядра) или вторая машина с judge-server. На сайте добавить судью в админке, мост подхватит его сам.
2. Больше процессов сайта. В `olymp-web.service` поставить `-w 9` (примерно 2 × ядра + 1) и `--worker-class gthread --threads 4`.
3. Второй сервер сайта. Тогда перед ними ставится nginx-балансировщик:

```nginx
upstream olymp_web {
    least_conn;
    server 10.10.8.226:8000;
    server <второй-сервер>:8000;
}
```

Для этого оба сервера должны видеть одну базу PostgreSQL, один Redis (кэш и сессии) и одну папку с тестами и медиа (NFS). Это отдельная работа, и делать её стоит, только если нагрузка реально упрётся в один сервер.
