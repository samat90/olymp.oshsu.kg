# Выкат обновления в понедельник (из сети ОшГУ)

Две машины: **olymp.oshsu.kg** (10.10.8.226) — сайт и база, **judge.oshsu.kg** (10.10.8.227) — судьи и запуск кода.
Обновление лежит в ветке `improvements-2026-10` на ноутбуке. Займёт около часа, сайт перезапускается на несколько секунд. Не делать во время олимпиады.

## База данных не удаляется

- Новые миграции 0159–0165 только добавляют: 2 новые таблицы (файлы компилятора, журнал нарушений), 3 новых поля у олимпиады, 4 новых языка, пункт меню «Компилятор», новый текст «О платформе». Все языки разрешаются во всех задачах; C# (Mono) убирается из списка разрешённых языков задач, вместо него C# (.NET 10). Старые посылки на Mono остаются. Ни одна таблица, пользователь, посылка или задача не удаляется.
- Это проверено на копии серверной базы от 21.10: после миграций ни в одной таблице не стало меньше записей (было 21 938 записей, стало 26 182: новые языки разрешены во всех задачах).
- Перед выкатом `deploy.sh` сам делает полный бэкап базы (`pg_dump`) в `/var/backups/olymp/deploy/<дата>/database.dump`. Ежедневный бэкап (`olymp-backup.sh`) тоже продолжает работать.
- Откат кода (`rollback.sh <папка>`) базу не трогает. Восстановление базы из бэкапа делается только вручную, с ключом `--database`, и только если что-то пошло совсем не так: оно заменит базу на состояние перед выкатом.

## 4. Сайт: выкат

```bash
git --git-dir=/home/admin/olymp.git show main:scripts/deploy.sh > /tmp/deploy.sh
bash /tmp/deploy.sh main
cd /var/www/olymp.oshsu.kg
cp scripts/server/post-receive /home/admin/olymp.git/hooks/post-receive
chmod +x /home/admin/olymp.git/hooks/post-receive
```

`deploy.sh` делает бэкап базы и кода, ставит пакеты, скачивает редактор и терминал, применяет миграции, собирает переводы и статику, перезапускает сайт и проверяет, что он отвечает (`OK: site answers 200`).

Если сайт не ответил: `bash scripts/rollback.sh /var/backups/olymp/deploy/<дата>` — вернёт старый код, база останется как есть.

Дальше любые обновления: `git push server improvements-2026-10:main` с ноутбука. Перед пушем ноутбук сам прогоняет все тесты, сервер сам делает бэкап и выкат.

## 8. Автовыкат с GitHub

Сервер раз в 5 минут сам проверяет ветку `main` на GitHub (`scripts/server/autodeploy.sh`, таймер `olymp-autodeploy.timer`). Снаружи к серверу ничего не открывается: он только сам обращается к GitHub.

Новый коммит выкатывается, только если:

- он подписан ключом из `/etc/olymp/allowed_signers` (подпись git через SSH-ключ);
- он продолжает уже выкаченную историю (переписанный или force-push `main` не принимается);
- сейчас не идёт олимпиада (выкат подождёт её окончания).

Дальше всё делает `deploy.sh`: бэкап базы и кода, миграции, перезапуск, проверка. Если сайт не поднялся, прежний код возвращается сам. Журнал: `/var/log/olymp/deploy.log`; сообщения в Telegram — если заполнен `/etc/olymp-monitor.env` (см. раздел 7).

Ноутбук подписывает коммиты сам (в репозитории включено `commit.gpgsign`, ключ `~/.ssh/olymp_signing`). Коммит, сделанный без этого ключа (в веб-интерфейсе GitHub, на другом компьютере), сервер не выкатит, пока поверх него не будет подписанного коммита с ноутбука.

Другой компьютер: создать ключ `ssh-keygen -t ed25519 -f ~/.ssh/olymp_signing`, в репозитории выполнить `git config gpg.format ssh`, `git config user.signingkey ~/.ssh/olymp_signing.pub`, `git config commit.gpgsign true`, и добавить строку `<почта> <открытый ключ>` в `/etc/olymp/allowed_signers` на сервере.

Управление на сервере:

```bash
sudo systemctl start olymp-autodeploy          # проверить и выкатить сейчас
sudo touch /etc/olymp/autodeploy.paused        # приостановить автовыкат
sudo rm /etc/olymp/autodeploy.paused           # возобновить
tail -n 50 /var/log/olymp/deploy.log
```

Служба запуска кода (`runner/`) обновляется тем же выкатом: в конце `deploy.sh` вызывает `scripts/server/sync_runner.sh`. Он сравнивает версию из `http://10.10.8.227:9910/health` с кодом в `runner/`, при расхождении по SSH (admin@olymp → admin@judge, без пароля) кладёт старые файлы в `/home/admin/olymp-runner/backup/<дата>`, копирует новые и перезапускает `olymp-runner`. Если новая служба не ответила за минуту, старые файлы возвращаются. База и проверка решений при этом не затрагиваются. Работающую версию видно снаружи: `https://olymp.oshsu.kg/runner/health`, поле `version`.

Изменения в `scripts/judge/` на judge.oshsu.kg сами не попадают: их копируют вручную, как в разделе 5.
