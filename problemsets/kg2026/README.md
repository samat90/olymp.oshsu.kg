## Как устроена папка задачи

- `problem.json` — название, ограничения, сложность, подзадачи (баллы и параметры генератора для каждого теста);
- `statement.md` — условие; `{{sample N}}`, `{{img файл ширина}}`, `{{photo файл подпись}}` подставляет сборщик;
- `sol.cpp` — эталонное решение (по нему считаются ответы);
- `alt.*` — второе, независимое решение: на всех тестах (кроме помеченных `noalt`) ответы должны совпасть;
- `brute.*` — медленный перебор: проверяет примеры и тесты подзадач с `"brute": true`;
- `gen.py` — генератор (детерминированный, зерно — последний параметр);
- `samples/`, `img/` — примеры и иллюстрации.

## Сборка и проверка (в WSL или Linux, нужны g++ и python3)

```bash
cd problemsets/kg2026
python3 build.py            # все задачи
python3 build.py taldyk     # одна задача
```

Сборщик останавливается при любом расхождении решений. Результат — `build/<задача>/` (тесты, готовое условие,
`manifest.json`, картинки). Папка `build/` не хранится в git: её всегда можно пересобрать.

## Загрузка на сайт

```bash
python manage.py import_problemset problemsets/kg2026/build --dry-run    # что будет добавлено
python manage.py import_problemset problemsets/kg2026/build --public
```

Команда только добавляет: задача с таким же названием пропускается, существующие задачи, тесты и файлы не меняются.
Номера новым задачам выдаются автоматически (следующие свободные шестизначные). Картинки копируются в
`MEDIA_ROOT/problems/kg2026/` (уже существующие файлы не перезаписываются).
